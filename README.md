# ALSOS — Public Website

> ἄλσος — grove, sacred grove.

로그인 이전의 브랜드·제품 소개 사이트입니다. 실제 학습, Lab 실행, 대시보드, XP 처리,
Garden 편집은 **이 저장소의 범위가 아닙니다** — `app.alsos.io`에서 제공됩니다.

```
www.alsos.io   공개 소개 사이트   ← 이 저장소
app.alsos.io   학습 플랫폼        별도 애플리케이션
```

```bash
npm install
npm run assets:hero   # 히어로 아트 생성 (최초 1회, 약 1분)
npm run dev
```

## 히어로 — the vault

숲 **안에 서서** 보는 그림이 아닙니다. **바닥에 누워 수관을 올려다보는** 그림입니다.

이 한 가지 결정이 전부입니다. 눈높이에서 찍은 숲은 풍경이고, 풍경은 앞에 서서 바라보는
것입니다. 바로 아래에서 올려다본 수관은 관객이 그 **안에 있는** 것입니다 — 기둥은 관객의
머리 뒤로 프레임을 빠져나가고, 가지는 머리 위에서 갈라지며, 모든 것이 잎사귀 사이 하나의
틈으로 수렴합니다. 한 글자를 읽기 전에 이미 고개가 젖혀져 있습니다.

그리고 그것이 정확히 ALSOS의 뜻입니다 — 빛을 향해 뻗는 성장을, 뻗는 쪽에서 올려다본 것.

**3D 엔진을 쓰지 않습니다.** Three.js도, R3F도, GSAP도 의존성에 없습니다.

| 레이어 | 내용 | 실패 시 |
| --- | --- | --- |
| 1. `HeroPoster` | 수관·빛의 정적 아트 (AVIF/WebP, LCP 대상) | — |
| 1b. `HeroReveal` | 틈에서 바깥으로 걷히는 그늘, CSS만 | 안 보임, 히어로는 완성 상태 |
| 2. `HeroTree` | 틈들이 차례로 불붙는 스프라이트 시트 | 안 보임, 히어로는 완성 상태 |
| 2b. `HeroMotes` | 빛 속의 먼지, CSS 세 겹 | — |
| 3. DOM | 로고·내비·카피·CTA·레일·마이크로카피 | — |

### 네 가지 원칙

**방사형이지, 수평이 아닙니다.** 인터넷의 모든 히어로는 레터박스 속 풍경입니다. 이것은
수렴합니다. 눈이 띠를 따라 훑는 대신 한 점으로 끌려가고, **현기증을 만드는 것은 수렴**입니다.

**중앙은 따뜻하고 가장자리는 차갑습니다.** 틈의 금빛에서 세이지와 청록을 거쳐 모서리의
깊은 청색으로. 방사형 색온도 구배는 단색이 결코 낼 수 없는 거리감을 만듭니다. 광휘는
**차가운 어둠과 따뜻한 빛의 대비**이기 때문입니다.

**선이 아니라 덩어리입니다.** 수관은 가지 다이어그램이 아니라, 가지가 꿰어져 있는 잎사귀
덩어리입니다. 네 겹의 잎 지층 사이에 나무가 끼어 있는 구조 — 이것이 숲과 거미줄을
가릅니다.

**실루엣과 림.** 모든 것이 거의 검고, 뒤의 밝은 하늘을 가로지르는 자리에서만 빛납니다.
역광이 수관을 아름답게 만듭니다 — 구조는 **음화로 그린 드로잉**입니다.

### 잎 지층 — 두 개의 주파수

이것이 전부의 요령입니다. 저주파 fbm 하나를 임계값으로 자르면 **해안선을 가진 대륙**이
나옵니다. 이끼 얼룩이지 나무가 아닙니다. 잎사귀는 작은 요소들이 **뭉치는** 것입니다:
넓은 필드가 잎 덩어리가 걸리는 자리를 정하고, 훨씬 고운 필드가 그 안에서 어느 잎이
빛을 받는지 정합니다. 피복률은 덩어리에서, 형태는 잎에서 옵니다.

```
하늘(여러 틈, sum이 아니라 max) → 빛줄기 → 먼 지층 0-1 → 나무(실루엣 + 림)
  → 가까운 지층 2-3 → 틈의 빛 → 확장 Reinhard 숄더 → 비네트·세이프에어리어
  → 240만 점 스티플
```

> 굵은 가지만 림을 얻습니다. 잔가지는 빛이 감고 돌 단면이 없어서 그냥 검게 남습니다.
> 두께와 무관하게 림을 주면 수관이 **빛나는 전선 다이어그램**이 됩니다.

> 모든 항이 가산이므로 밝은 영역은 1을 훌쩍 넘고, 램프가 그걸 태양에 고정하면
> 부드러운 감쇠가 **딱딱한 흰 쐐기**로 변합니다. 확장 Reinhard(화이트 포인트가 있는)로
> 숄더를 굴려야 빛이 아무리 쌓여도 부드럽게 남습니다.

### 성장 애니메이션

**두 겹입니다. 스프라이트 혼자서는 이 그림을 움직일 수 없기 때문입니다.**

플레이트가 완성된 상태입니다 — 이미 전부 밝습니다. 그래서 가산 레이어는 히어로를 쉬는
상태보다 *더 밝게* 만드는 것밖에 못 하고, 그건 도착이 아니라 플래시로 읽힙니다.
움직임은 **그늘이 걷히는 쪽**에서 나와야 합니다.

`HeroReveal` — 틈에서 투명하고 테두리 밖으로 불투명한 어두운 원반이 천정에서 바깥으로
확대되며 사라집니다. 눈에 보이는 것은 빛이 틈에서 모서리로 수관을 통해 번지는 것이고,
끝나는 지점은 정확히 원래의 아트입니다. CSS만 쓰며 `opacity`와 `scale`만 애니메이트합니다.
완전히 검게 가리지는 않습니다 — 포스터가 LCP 요소인데 2초를 비우면 빠른 히어로가 느리게
느껴지니까요. 쉬는 상태는 `opacity: 0`이고 애니메이션만 그걸 들어 올립니다. 의도된
설계입니다: 애니메이션이 아예 돌지 않는 환경에서의 실패가 **검게 덮인 히어로가 아니라
보이지 않는 요소**여야 하기 때문입니다.

`HeroTree` — 수관에 실제로 뚫린 구멍들이 틈에서 바깥으로 차례로 불붙습니다.

이 스프라이트를 두 번 잘못 만들었습니다. 처음엔 가지 골격을 따라 그렸는데, 플레이트가
그 나무를 실루엣으로 그리므로 제 그림자 위에 밝은 획을 얹는 꼴이었습니다 — 작품 위에
던져진 케이블 도면. 게다가 올려다보는 사람은 잎을 보지 골격을 보지 않습니다.
두 번째로 **잎 가장자리**에 불을 붙였는데, 그 가장자리는 잎 뭉치마다 닫힌 고리라서
레이스가 그려졌습니다 — 화면이 서리처럼 덮였습니다. 불붙는 건 **틈**입니다. 완성된
휘도의 가파른 거듭제곱으로 가중하면 상위 몇 퍼센트만 남고, 텍스처가 아니라 반짝임이
됩니다.

봉우리 두 개가 전부입니다. `flare`는 한 점이 도착하는 중간에 정점을 찍고 끝날 때 사라지는
혹 — 눈이 움직임으로 읽는 유일한 항입니다. 첫 버전은 이게 쉬는 값보다 *어두웠고*, 그래서
파면이 아예 보이지 않았습니다. `rest`는 남는 값이고 거의 0이어야 합니다. 플레이트가 같은
것을 이미 그리므로, 쉬는 값이 flare에 조금이라도 가까우면 두 번 그려집니다. 최종 프레임이
플레이트를 바꾸는 양은 측정으로 **평균 1/255**입니다.

레이어는 `screen`으로 합성합니다 — 빛이지 물감이 아니니까요. 검은 곳은 그대로 두고 불붙은
곳만 들어 올립니다. **블렌드는 스프라이트가 아니라 스테이지에 겁니다.** `container-type:
size`가 스테이지를 쌓임 맥락으로 만들기 때문에, 자식에 건 블렌드는 포스터가 아니라 스테이지
자신의 빈 배경과 섞이고 — 스프라이트가 불투명하므로 — 플레이트 위에 검은 사각형이 됩니다.

스프라이트는 플레이트와 같은 구도를 추적하므로 프레임에 늘려 붙일 수 없습니다. 플레이트가
아닌 비율의 뷰포트에서는 포스터가 cover로 잘리고 스프라이트는 미끄러집니다. `.treeStage`가
그 crop을 정확히 재현합니다 — 같은 비율, 같은 앵커, cover 크기, 뷰포트가 아니라 히어로
박스를 따르도록 컨테이너 단위로.

`prefers-reduced-motion`에서 원반은 걷힐 것이 없고(이미 열려 있고), 스프라이트는 마지막
프레임에 고정됩니다.

## 좌표 계약

`public/assets/hero/manifest.json`이 아트와 DOM 사이의 계약입니다. 개발자가 위치를 눈으로
추정하지 않습니다 — `zenith`(수관의 틈)는 포스터의 `object-position`, 스프라이트 스테이지의
앵커, 먼지 레이어의 마스크 중심을 **동시에** 정합니다. 플레이트를 다시 렌더하면 셋 다
같이 움직입니다.

`safe`는 장식이 아닙니다. 카피와 레일의 실측 대비가 여기에 달려 있으므로, 눈이 아니라
렌더 결과에 맞춰 조정합니다.

## 데이터에 관한 원칙

**가짜 지표를 쓰지 않습니다.** 우측 레일에는 학습자 수·성공률·Lab 수 대신
세 개의 제품 개념(STRUCTURED PATHS / HANDS-ON PRACTICE / LIVING PROFILE)을 둡니다.
실제 데이터가 검증되기 전까지 숫자 지표는 노출하지 않으며, 테스트가 이를 강제합니다.

## 접근성

* 모든 카피와 링크가 DOM에 존재합니다. 장식 레이어는 `aria-hidden`입니다.
* JavaScript 없이도 헤드라인과 CTA가 표시됩니다.
* 스프라이트가 로드되지 않아도 정적 포스터로 히어로가 완결됩니다.
* `prefers-reduced-motion: reduce`에서 나무는 최종 상태로 정지하고 먼지는 멈춥니다.
* 포커스 링을 제거하지 않으며, 첫 탭 스톱은 건너뛰기 링크입니다.

플레이트는 시드에서 다시 생성되므로 **밝기가 한 번 승인받고 끝나는 상수가 아닙니다.**
노출·세이프에어리어·팔레트를 건드리면 아무도 모르게 글자가 밝은 잎사귀 위로 올라갈 수
있습니다. 그래서 텍스트를 숨긴 채 합성된 배경을 촬영해 각 글줄 아래의 95퍼센타일 휘도를
재고 WCAG AA로 강제합니다 (`tests/e2e/hero.spec.ts`). 평균이 아니라 95퍼센타일인 이유는,
평균은 실제로 단어를 삼키는 밝은 얼룩을 감추기 때문입니다.

내비게이션은 수관에서 가장 밝은 곳을 지납니다. 아트를 그만큼 어둡게 하면 프레임 상단에
띠가 보이므로, 그늘은 DOM에 둡니다 — 위 가장자리에서 떨어지는 부드러운 스크림, 테두리도
자체 배경색도 없이. 눈에 가장 가까운 잎사귀가 프레임 가장자리의 잎사귀이고 그것이 vault에서
가장 어두운 것이니, 사실이기도 합니다.

## 알려진 범위

* 히어로 아트는 시드 기반 **절차적 생성**입니다. 회화 에셋으로 교체할 때는
  manifest 계약만 맞추면 컴포넌트를 수정하지 않아도 됩니다.
* `src/styles/tokens.css`의 램프는 `scripts/build-hero.mjs`의 `SKY`를 열세 지점에서
  샘플한 **문자 그대로의 값**입니다. DOM 크롬과 아트가 같은 빛 안에 있는 것은 눈대중이
  아니라 구조입니다.
* 디스플레이 서체는 커스텀 "ALSOS Grid"가 제작되기 전까지 Pixelify Sans를 대역으로 씁니다.
  8비트 게임 서체가 아니라 픽셀 그리드 위의 정상적인 타이포 비례를 가진 face입니다 —
  §5.1이 사이트 전체가 고전 게임처럼 보이는 것을 경계합니다.
  워드마크는 서체가 아니라 12×12 모듈 그리드 위의 SVG 패스입니다.
* 데스크톱·모바일 두 구도가 각자의 아트를 가집니다. 태블릿은 데스크톱 플레이트를
  cover로 자릅니다 — 전용 구도는 PR3입니다.
